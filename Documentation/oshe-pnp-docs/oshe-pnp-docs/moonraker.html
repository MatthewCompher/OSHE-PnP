Moonraker, Cameras & Integration

Moonraker is the web API that sits between Klipper and everything else. Mainsail, KlipperScreen and pnpvision all talk to Klipper through it. This page covers its configuration, the camera streams, and how pnpvision and the macros connect to it.

How the pieces connect

FromToHow
Mainsail (browser)MoonrakerHTTP/WebSocket on port 7125, via the Pi's web server
KlipperScreenMoonrakerSame API, on the Pi
pnpvisionMoonrakerHTTP to http://localhost:7125: sends G-code and reads machine state
pnpvisionCamerasReads snapshots from crowsnest, so the dashboard views keep working
Klipper macrospnpvisiongcode_shell_command runs scripts that start pnpvision in the background

Moonraker endpoints pnpvision uses

EndpointUse
POST /printer/gcode/scriptSend G-code (moves, light macros, etc.)
GET /printer/objects/queryRead state such as the toolhead position
GET /printer/objects/listList available Klipper objects

The Moonraker address is set in Software/pnpvision/config.toml under [moonraker] url.

Why the shell scripts run in the background

When a macro like VISION_HOME starts pnpvision, pnpvision sends its moves back to Klipper through Moonraker. If the macro waited for the script to finish, Klipper would be waiting for the script while the script waits for Klipper: a deadlock. So scripts/vision_home.sh and scripts/run_job.sh start pnpvision with setsid nohup … & and return right away. Results show up in the Mainsail console and in log files under results/.

moonraker.conf

The prototype's file is in Software/Klipper/from-pi/moonraker.conf. On the Pi it lives in ~/printer_data/config/. Main sections:

SectionSetting
[server]Listens on all addresses, port 7125
[authorization]Trusts local network ranges (10.x, 172.16–31.x, 192.168.x, link-local, localhost) and allows *.local / *.lan browsers
[file_manager]Object processing off (saves memory on the 1 GB Pi)
[history], [octoprint_compat], [announcements]Job history, OctoPrint-compatible API, Mainsail news
[update_manager …]Updates for Mainsail, mainsail-config, crowsnest, sonar, Obico and klipper-led_effect from Mainsail's Update Manager
Security: trusted clients can control the machine without logging in. Only connect it to a network you trust.

ExposureAutomaticFixed (see below)
  • Use /dev/v4l/by-id/… device paths so the cameras keep their roles after a reboot.
  • The resolution in crowsnest.conf, in pnpvision's config.toml, and in the lens calibration file must all match.

Fixed exposure for the up camera

Automatic exposure readjusts every time the light switches, giving washed-out frames. The up camera uses fixed settings in its [cam 2] section:

v4l2ctl: auto_exposure=1,exposure_dynamic_framerate=0,white_balance_automatic=0,power_line_frequency=2,exposure_time_absolute=80

To find the right value for your camera, list its controls with v4l2-ctl -d <device> -L, try values live with v4l2-ctl -d <device> -c …, and aim for 0–0.3% saturated pixels (pnpvision's focus-sweep reports this).

Undistorted camera views

Two optional services, undistort-down and undistort-up (ports 8090 and 8091), show lens-corrected views with a crosshair reticle in Mainsail. They come from Archive/USB Camera Calibration Vibecode Project/undistort_stream.py; add --motion for millimeter tick marks. Restart them after recalibrating.

Print list launchers

pnpvision make-launchers writes small PNP_<job>.gcode and PNP_<job>_ALIGN.gcode files into Moonraker's G-code folder. They appear in the print list in Mainsail and on the touchscreen; selecting one runs RUN_JOB. See G-code Macros.

Troubleshooting

ProblemFix
Moonraker warning about crowsnest install_scriptIn moonraker.conf under [update_manager crowsnest], set install_script: tools/install.sh.
Camera shows "NO SIGNAL" or crowsnest won't startCheck ~/printer_data/logs/crowsnest.log. "ustreamer not found" means crowsnest must be reinstalled: cd ~/crowsnest && sudo make install, inside tmux.
pnpvision can't reach the machineCheck Moonraker is running and [moonraker] url in config.toml is http://localhost:7125.
Touchscreen job dialogs don't appearUse PNP_CONTINUE or PNP_STOP from the console. Check that your KlipperScreen version shows action:prompt dialogs.
