pnpvision: Calibration & Running Jobs

pnpvision is the Python program on the Pi that gives the machine its accuracy. It calibrates the cameras to the machine, finds the board, checks every part on the nozzle, and runs jobs. It moves the machine through Moonraker and reads the cameras from crowsnest. The code is in Software/pnpvision.

Every vision command lifts the nozzle to a safe travel height (Z 30) before any X/Y move. Remember: on this machine a larger Z is lower.

Install on the Pi

python3 -m venv ~/venv-pnp
        cd ~/OSHE-PnP/Software/pnpvision
        ~/venv-pnp/bin/pip install --only-binary=:all: -r requirements.txt

Always use --only-binary=:all:: otherwise pip may try to build OpenCV from source, which runs a 1 GB Pi out of memory. Run long installs inside tmux.

Commands run from Software/pnpvision as ~/venv-pnp/bin/python -m pnpvision <command>. Machine-specific settings (travel limits, safe Z, camera URLs and sizes, lights) are in config.toml. Measured calibration results are saved in calibration/machine.json.

Tests that need no hardware:

python tests/test_offline.py && python tests/test_datum.py

Calibration

Do these once per machine, in order. The Redo when column says what makes a step need repeating.

#StepCommandRedo when
1Lens calibration for each camera, using a ChArUco board (7×5, 8 mm squares, 6 mm markers, DICT_4X4). Copy the .npz into calibration/.calib_capture.py (in Archive), then check-lensLens refocused or swapped; resolution changed
2Check images and tune exposure and lighting.snapshot --cam up|down-
3Down-camera motion map: how camera pixels map to machine mm. Use a dark ~3 mm dot, fixed in place, at PCB-top height.calibrate-motion --cam down --step 3Camera moved or refocused
4Repeatability check (optional diagnostic).repeatability --n 20 (--home-every 5 to include homing)Mechanical changes
5Teach visual homing with datum dot 0 under the crosshair. This defines the machine frame for everything after it.home --teach --polarity bright --thresh 230Datum or down camera moved (then redo everything below)
6VISION_HOME button: install the G-Code Shell Command extension (KIAUH) and the VISION_HOME sections in printer.cfg.-New Pi
7Down camera → nozzle offset: put the nozzle over a dot by eye, 3 runs.calibrate-offsetCamera or nozzle holder moved
8Up-camera motion map and center: up light on, nozzle tip in focus over the up camera.find-dot --cam up to tune, then calibrate-motion --cam up --find-center --step 1Up camera moved or refocused
9Datum teach and reference: whole grid centered and sharp.datum --teach, datum --referenceDatum moved
10Up-camera fixed exposure (see Moonraker).focus-sweep to check saturationCamera, light or lens changed
11Center on the real nozzle tip (not the holder face).calibrate-motion --cam up --center-only --keep-offsetTip changed or bent
12Inspection height with a part on the nozzle (Z 34.5 for 0805 on the prototype).focus-sweep, judged on the saved imagesTip or holder changed
13Nozzle rotation direction: turn 30° steps with a part on the nozzle and inspect.inspect-up, set [rotation] direction in config.tomlRotation motor or tip changed
14Refine the offset by placing parts: spare parts on a bare board, pick and place them, measure where they land.place-test, then --apply-offset, check with --correctNozzle, head or a camera moved
15Nozzle tips: record each tip's board-touch Z and inspection Z.tip <NAME> --board-touch-z Z --inspect-z Z [--current]New tip
16Feeders: teach each feeder's pick spot (see below).teach-feederFeeder moved
17Reject bin: nozzle over the bin at safe Z.teach-binBin moved
The motion map absorbs any camera rotation, mirroring or X/Y scale difference, so the cameras don't need to be squared up mechanically. On the prototype the down camera is rotated 0.5° and the up camera 90°; both work fine.

Running a job

  1. Home: VISION_HOME from the console; wait for its result line. Then UP_LIGHT_ON.
  2. Align the board: put the board on the plate, center the down camera by eye on alignment pad A, then: 
    python -m pnpvision align-board "jobs/<board>-top.job.json" --rot <board rotation, degrees CCW>
    It photographs around each predicted pad, finds the pads, fits position and rotation, and saves the board pose. Images go in align_<time>/.
  3. Dry run: the down camera photographs every placement spot with a crosshair, no parts: 
    python -m pnpvision run-job "jobs/<board>-top.job.json" --dry-run
  4. Run (optionally only some parts, or without feeders): 
    python -m pnpvision run-job "jobs/<board>-top.job.json" [--only R1 R2 ...] [--no-feeders]
    With --no-feeders you put a part in the pocket by hand when asked. The runner asks you to swap nozzle tips when needed, and re-centers automatically.

For each part the runner picks it, checks it over the up camera, corrects offset and angle, and places it. Each part prints its cycle time per phase; the end prints seconds per part and parts per hour. Results go in results/job_<time>.json, with up-camera images in job_<time>/.

From the touchscreen

Run make-launchers (add --no-feeders until the feeders work) to put PNP_<job>.gcode files in the print list, then select one on the touchscreen. See G-code Macros.

Feeders

  1. Flash Software/feeder_nano/feeder_nano.ino to the Arduino Nano (set SERVO_PINS first).
  2. Plug the Nano into the Pi and set [feeders] port in config.toml.
  3. Test: python -m pnpvision feed 1 --times 3
  4. Teach each slot: jog the nozzle down until it just touches the part in the pick pocket, then 
    python -m pnpvision teach-feeder F1 --servo 1 --package R_0805_2012Metric
    For a manual track (no servo), use --manual --tape-angle <deg>. The pick position then refines itself from the up camera.

The Nano accepts simple serial commands at 115200 baud: F<n> queues one stroke on feeder n, A<n>,<deg> moves a servo to an angle, and ? reports the state.

Recovering after the machine was disturbed

If the head was removed, the nozzle swapped, or anything bumped, run (nozzle empty, up light on, after VISION_HOME):

python -m pnpvision check-machine

It checks that printer.cfg still has the pnpvision sections, the homing dot is on the crosshair, both camera maps still predict small jogs correctly, and the nozzle is where the up camera expects. It prints OK, or REDO with the step to repeat. --apply saves a moved nozzle center.

Results so far (prototype, November 2026)

  • Repeatability about 0.01 mm; sensorless homing alone lands 0.1–2 mm off, which visual homing fixes.
  • Board alignment on the test PCB: residuals ≤ 0.037 mm, and the right pads were found even when starting 1.7 mm off.
  • Placement tests with 0805 resistors: parts landed 0.03–0.17 mm from target, with angle errors under 1°.
  • Rotation to 45° landed about 4–5° short; this is acceptable for 0805 parts (reflow straightens chips) and a correction can be added later.
⚠ Verify: the full job runner and the touchscreen launch have been tested mostly against a simulator. Update these results after the first full job.

Lessons learned

  • Calibration targets must not move. A loose paper dot slid about 0.05 mm during fast moves and looked like a machine error. Tape or glue it.
  • Measure features after centering them on the crosshair. The down camera is only ~11.5 mm from the work, so image scale changes about 9% per mm of height; off-center readings are unreliable.
  • The up camera may not look straight up. Lowering the nozzle from Z 20 to Z 38 moved it ~1.6 mm in the image, so the up camera is calibrated and used at one fixed height.
  • Use square pixels when undistorting. OpenCV's default made round dots look 24% oval.
  • Textured prints need a fixed threshold. A white dot on a sparkly print broke automatic thresholding.
  • LED noise affects vision. A flickering purple light makes white features much darker to the camera. See LED wiring tips.
